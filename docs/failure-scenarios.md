# FinOrchestrator — Failure Scenarios & Resilience Guide

FinOrchestrator is engineered with high fault tolerance, defensive coding patterns, and graceful degradation strategies across every layer of the distributed stack.

---

## 1. Failure Matrix & Automated Recovery

| Failure Scenario | Impacted Component | Detection Mechanism | System Reaction & Recovery Strategy | User Experience |
|---|---|---|---|---|
| **Downstream Finance Service Down** | `mcp-finance-server`, `ai-orchestrator` | Resilience4j Circuit Breaker (Timeout 3000ms / 50% failures) | Circuit opens (`OPEN`); MCP server returns cached ledger balances with staleness timestamp. | User receives balance with notice: *"Showing cached ledger balance as of 18:00."* |
| **Ollama Local LLM Not Running** | `ai-orchestrator` (Local Tier) | HTTP Connection Refused / Read Timeout (5000ms) | `HybridLLMRouter` catches `ResourceAccessException` and automatically routes query to Cloud Groq LPU (or MockLLMProvider). | Zero user impact; query completes normally in < 400ms. |
| **Cloud Groq LPU Rate Limit (HTTP 429)** | `ai-orchestrator` (Cloud Tier) | HTTP 429 Status Code / Groq API Exception | Router automatically fails over to Local Ollama. If Ollama is unavailable, triggers deterministic `MockLLMProvider`. | Query answers successfully without throwing 500 error. |
| **Vector Store (Qdrant) Unreachable** | `document-service`, `mcp-contract-server` | Vector client socket timeout (2000ms) | `VectorStoreService` activates in-memory cosine fallback populated with seeded contract chunks. | Document clauses and page numbers return successfully. |
| **Kafka Broker Cluster Down** | `finance-service`, `risk-service` | Kafka producer ack timeout | Producers buffer events in local memory; synchronous REST operations succeed unaffected. Failed events are published once Kafka recovers. | User transaction is saved immediately; risk analysis runs asynchronously upon recovery. |
| **Concurrent Account Balance Update Race** | `finance-service` | JPA `OptimisticLockException` | Service automatically retries the debit/credit operation with refreshed entity version up to 3 times. | Seamless execution; balance remains mathematically exact. |
| **API Gateway Spike / DDoS Attack** | `api-gateway` | Redis Token Bucket Rate Limiter | When bucket capacity (60 req/min) is exhausted, Gateway immediately returns HTTP 429 with `Retry-After` header. | Malicious client is throttled without impacting downstream services. |

## 2. Circuit Breaker Configuration (`Resilience4j`)

In `ai-orchestrator` and `api-gateway`:

```yaml
resilience4j:
  circuitbreaker:
    instances:
      mcpClient:
        slidingWindowSize: 10
        minimumNumberOfCalls: 5
        failureRateThreshold: 50
        waitDurationInOpenState: 10000ms
        permittedNumberOfCallsInHalfOpenState: 3
  retry:
    instances:
      mcpClient:
        maxAttempts: 3
        waitDuration: 500ms
        exponentialBackoffMultiplier: 2
  timelimiter:
    instances:
      mcpClient:
        timeoutDuration: 3000ms
```

## 3. Strict Guardrails Against AI Hallucinations

1. **System Prompt Guardrails**:
   Every prompt generated by `ResponseSynthesizer` enforces:
   - *"Only reference numbers marked with `[FACT]` or `[CALCULATION]`. Never recalculate or alter numbers."*
   - *"If asked about contracts, cite the exact clause and page number under `[CONTRACT_INFO]`."*
   - *"If data is missing from tool results, state: 'Data unavailable in current records' rather than guessing."*
2. **Post-Synthesis Deterministic Verifier**:
   Before returning an answer to the user, the Orchestrator checks that every numeric value in the generated explanation matches a number present in the tool results. If any unauthorized number is detected, the answer is flagged as `REJECTED` and the verified backend calculation is displayed directly.
